# Формат снимка состояния SGF

## Назначение и границы

Снимок сохраняет состояние одного экземпляра `EventValidator`, необходимое для продолжения валидации после перезапуска:

- состояние дедупликации `event_id`;
- FIFO-порядок идентификаторов и ёмкость ограниченного окна;
- sequence-watermark для каждой пары `source_id/instrument_id`.

Снимок не является журналом входных событий, не содержит исходные рыночные данные и не позволяет воспроизвести историю до точки снимка. Для полного replay внешний слой должен хранить журнал событий и связывать его позицию с точкой снимка через JournalCheckpoint (следующий offset и hash последней записи). Checkpoint должен входить в тот же атомарно публикуемый durable manifest, что и snapshot.

## Версионирование

- Магическое значение: ASCII `SGFS`.
- Версия формата: unsigned 16-bit little-endian, текущая версия `1`.
- Неизвестная версия отклоняется. Автоматическое угадывание или частичное восстановление запрещено.
- Числовые поля кодируются little-endian.
- Строки кодируются как длина unsigned 32-bit little-endian, затем UTF-8 bytes.

## Канонический порядок

1. Заголовок: magic, версия.
2. Режим дедупликации: `0` для неограниченного, `1` для FIFO.
3. Ёмкость: unsigned 64-bit; для неограниченного режима строго `0`.
4. Количество event_id: unsigned 32-bit.
5. Event ID:
   - FIFO: строго в порядке от старейшего к новейшему, без сортировки;
   - неограниченный режим: лексикографически по UTF-8 строкам.
6. Количество sequence-watermark: unsigned 32-bit.
7. Записи потоков: `source_id`, `instrument_id`, `sequence`; сортировка по паре `(source_id, instrument_id)`.
8. SHA-256 от всех предшествующих байтов: 32 байта.

Для одинакового состояния кодирование должно давать одинаковую последовательность байтов независимо от порядка обхода HashMap/HashSet.

## Проверки при восстановлении

Восстановление выполняется только после проверки SHA-256 и затем проверяет:

- magic и поддерживаемую версию;
- допустимый режим и согласованность ёмкости;
- отсутствие пустых идентификаторов;
- корректный UTF-8;
- отсутствие дублирующихся event_id и потоков;
- строгий канонический порядок записей;
- размер FIFO-окна не выше ёмкости;
- отсутствие усечённых и лишних конечных данных.

При любой ошибке снимок целиком отклоняется. Частичное восстановление запрещено.

## Безопасность контрольной суммы

SHA-256 выявляет случайное повреждение и несогласованность байтов. Он не является подписью и не подтверждает источник снимка: сторона, способная изменить снимок, может пересчитать контрольную сумму. Для защиты от подмены внешний storage-слой должен обеспечивать аутентификацию, контроль доступа и при необходимости подпись/MAC.

## Ответственность storage-слоя

Ядро предоставляет только `encode_snapshot` и `restore_snapshot`. Внешний слой отвечает за:

- атомарную запись и замену снимка;
- защиту от одновременной записи;
- долговечность и резервирование;
- выбор момента снимка;
- согласование позиции снимка с журналом событий;
- восстановление журнала после снимка;
- защиту от подмены и отката к устаревшему снимку.

Снимок следует записывать во временный объект, проверять его целостность и только затем атомарно публиковать как актуальный. Конкретный протокол зависит от выбранного backend и не должен попадать в доменное ядро.
