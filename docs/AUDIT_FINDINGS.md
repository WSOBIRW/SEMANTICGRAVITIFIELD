# Аудит реализации SGF PR #2–#8

## 1. Назначение
Документ фиксирует проверяемые расхождения между фактическим кодом и архитектурными требованиями SGF. Findings не означают автоматически, что соответствующая функция полностью отсутствует: указывается конкретный публичный путь, условие воспроизведения и требуемое исправление.

## 2. Область аудита
Проверены merged PR #2–#8, текущие реализации event, validation, prevention, snapshot, journal и recovery, а также замечания автоматического ревью в обсуждениях PR. Проверка выполнена по доступному состоянию main после архитектурного документирования.

## 3. Чем не является
Этот документ не является заявлением о полном security audit, формальной верификации или прохождении CI. Для каждого исправления требуются отдельные тесты и проверка CI на точном commit SHA. Отсутствие finding в этом документе не доказывает отсутствие дефектов.

## 4. Findings

### SGF-AUDIT-001 — Конфигурация ограниченной дедупликации недоступна через ErrorPreventionEngine
- Приоритет: P2.
- Статус: CLOSED в PR #9.
- Доказательство: merge commit `8b9503524e6dbf152d9dabc5c2233f101eac90ef`; PR CI на merge ref `fd19a8b8ced31340f2110334f86eba9a48065d7e` — fmt, Clippy и тесты PASS.
- Затронутый компонент: src/prevention.rs.
- Условие: внешний потребитель использует публичный ErrorPreventionEngine::new()/inspect API.
- Наблюдение: ErrorPreventionEngine владеет приватным EventValidator, конструктор всегда создаёт его с неограниченной дедупликацией. Публичный потребитель не может выбрать with_dedup_capacity.
- Риск: длительно работающий потребитель на основном публичном API может неограниченно накапливать event_id, несмотря на наличие bounded FIFO в EventValidator.
- Требуемое исправление: предоставить конструктор ErrorPreventionEngine с явной NonZeroUsize ёмкостью; сохранить текущий new() без скрытого изменения семантики.
- Критерий закрытия: тест публичного EPE API доказывает вытеснение старого ID и ограниченное окно.

### SGF-AUDIT-002 — Reset потока недоступен через ErrorPreventionEngine
- Приоритет: P2.
- Статус: CLOSED в PR #9.
- Доказательство: merge commit `8b9503524e6dbf152d9dabc5c2233f101eac90ef`; PR CI на merge ref `fd19a8b8ced31340f2110334f86eba9a48065d7e` — fmt, Clippy и тесты PASS.
- Затронутый компонент: src/prevention.rs.
- Условие: потребитель использует ErrorPreventionEngine::inspect и получает reconnect с перезапуском sequence.
- Наблюдение: внутренний EventValidator имеет reset_stream, но он приватен внутри ErrorPreventionEngine; публичный EPE API не предоставляет forwarding method.
- Риск: после reconnect поток, начинающий sequence заново, продолжает отклоняться как NonIncreasingSequence.
- Требуемое исправление: предоставить явный метод reset_stream(source_id, instrument_id) на ErrorPreventionEngine, возвращающий результат внутреннего вызова. Автоматически сбрасывать состояние нельзя.
- Критерий закрытия: интеграционный тест через публичный EPE API подтверждает reset выбранного потока и сохранение дедупликации/состояния остальных потоков.

### SGF-AUDIT-003 — Неограниченное предварительное выделение памяти при восстановлении snapshot
- Приоритет: P2, безопасность доступности.
- Статус: OPEN до исправления.
- Затронутый компонент: src/snapshot.rs.
- Условие: snapshot поступает из недоверенного или повреждённого внешнего хранилища и содержит checksum, пересчитанный для сформированного входа.
- Наблюдение: id_count ограничен только размером оставшихся байтов и передаётся в HashSet::with_capacity до проверки более строгого ограничения bounded FIFO capacity. SHA-256 не является ключевым MAC, поэтому атакующий может сформировать самосогласованный digest.
- Риск: чрезмерное выделение памяти или отказ процесса до возврата структурированной SnapshotError.
- Требуемое исправление: в bounded режиме проверять id_count против capacity до обработки; не выполнять eager allocation по недоверенному счётчику. Сохранять строгую проверку структуры и порядка.
- Критерий закрытия: checksum-valid snapshot с количеством ID выше capacity отклоняется как InvalidCapacity до выделения таблицы; тесты покрывают чрезмерные счётчики и пустые строки.

### SGF-AUDIT-004 — Монотонность recovery generation не обеспечивается формой контракта
- Приоритет: P1 перед production storage.
- Статус: OPEN — архитектурный контракт/будущий backend.
- Затронутый компонент: RecoveryManifest и RecoveryStorage.
- Наблюдение: manifest содержит generation, но RecoveryPackage::restore проверяет digest/длину/checkpoint и не может установить, что поколение новее ранее принятого. RecoveryStorage::commit_generation не задаёт compare-and-swap/expected generation и явное поведение при конкурентном или устаревшем commit.
- Риск: backend может опубликовать корректный по хешам, но устаревший generation или потерять обновление при гонке writers.
- Требуемое исправление: до production backend определить атомарную политику единственного писателя либо optimistic concurrency с ожидаемым предыдущим generation; закрепить монотонность и rollback policy в контракте. Проверка generation выполняется относительно доверенного текущего состояния, а не только внутри автономного manifest.
- Критерий закрытия: контракт и backend тестируют stale writer, конкурирующие commit, rollback и восстановление после сбоя.

## 5. Исправленные в последующих этапах замечания
- PR #2: отсутствие диагностики sequence gap устранено в последующей временной семантике; текущий EventValidator выдаёт SequenceGap warning и продвигает watermark.
- PR #7: reset_stream включён в журнал отдельной управляющей записью; replay применяет reset до следующих событий.
- PR #8: RecoveryManifest связывает snapshot, длину journal, anchor и expected_end; RecoveryPackage проверяет пакет и не возвращает частичный валидатор.

## 6. Критерии соответствия аудита
Finding закрывается только после изменения кода, добавления регрессионного теста, независимой проверки diff и подтверждённого CI для точного SHA. Изменение статуса в документации без доказательства исправления запрещено.
