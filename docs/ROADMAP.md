# Дорожная карта SGF

## Принцип

Развитие ведётся небольшими проверяемыми этапами. Не строить универсальную инфраструктуру заранее. Каждая подсистема появляется после фиксации контракта, тестируемых требований и измеримой необходимости.

## Этап 0. Основание проекта
- [x] Создать репозиторий и зафиксировать назначение.
- [x] Зафиксировать независимость от торговых ядер.
- [x] Определить два основных контура: обнаружение возможностей и предотвращение ошибок.
- [x] Зафиксировать базовые границы безопасности.
- [x] Описать нейтральный контракт интеграции.
- [x] Описать классы ошибок и статусы защитного ответа.

## Этап 1. Проверка требований и контрактов
- [ ] Провести критический аудит документов и устранить противоречия.
- [ ] Определить минимальный набор рыночных событий и торгового состояния.
- [ ] Определить точность времени, единицы, идентификаторы и provenance.
- [ ] Создать машиночитаемую схему сообщений.
- [ ] Создать тестовые фикстуры и негативные сценарии.
- [ ] Зафиксировать поведение при отказе и устаревании данных.

Критерий завершения: независимый потребитель может реализовать контракт без знания внутренних модулей SGF.

## Этап 2. Минимальное исполняемое ядро
- [ ] Реализовать проверку схемы, происхождения и временной последовательности.
- [ ] Реализовать детерминированную обработку событий.
- [ ] Реализовать журнал аудита и воспроизводимость.
- [ ] Реализовать базовые проверки EPE без машинного обучения.
- [ ] Создать CLI для воспроизведения тестовых потоков.

Критерий завершения: одинаковый набор входных событий даёт воспроизводимый результат, а негативные тесты выявляют заданные дефекты.

## Этап 3. Первый интеграционный адаптер
- [ ] Реализовать адаптер TRADINGCORE как внешнего потребителя.
- [ ] Начать с режима наблюдения.
- [ ] Проверить задержки, потери, дубликаты и восстановление соединения.
- [ ] Сопоставить вердикты SGF с независимыми проверками TRADINGCORE.

Критерий завершения: SGF можно отключить без нарушения торгового ядра; отсутствие SGF не даёт разрешения на сделку.

## Этап 4. Исследовательский движок
- [ ] Формализовать исходные гипотезы семантической гравитации.
- [ ] Восстановить и проверить прежние идеи SGF, включая Φ-энергию капитала и Zeta Intent, не принимая их истинность заранее.
- [ ] Реализовать базовые модели и сравнения.
- [ ] Добавить обнаружение неизвестных структур как генерацию гипотез.
- [ ] Ввести независимую проверку и контроль множественных гипотез.

Критерий завершения: обнаружение отделено от подтверждения; ни одна новая структура не становится торговым сигналом без проверки.

## Этап 5. Экономическая проверка
- [ ] Сравнить торговую систему без SGF и с SGF на одинаковых данных.
- [ ] Измерить чистое математическое ожидание, просадку, частоту сделок и издержки.
- [ ] Провести Out-of-Sample и Walk-Forward проверку.
- [ ] Проверить устойчивость на независимых источниках и режимах рынка.
- [ ] Провести Paper Trading без отправки реальных ордеров.

Критерий завершения: воспроизводимое улучшение результата или снижение риска без утечки будущего и без подгонки под тестовую выборку.

## Этап 6. Расширение
- [ ] Разработать SDK для дополнительных языков.
- [ ] Добавить новые торговые адаптеры.
- [ ] Изучить требования к локальному и удалённому развёртыванию.
- [ ] Проверить модель лицензирования и коммерческую ценность.

## Запреты до доказательства необходимости

- Не встраивать SGF внутрь TRADINGCORE.
- Не давать SGF прямой доступ к торговым ключам.
- Не реализовывать автоматическую торговлю в SGF.
- Не добавлять тяжёлые зависимости без измеренной необходимости.
- Не фиксировать транспорт, хранилище или вычислительную платформу преждевременно.
- Не заявлять о торговом преимуществе до независимой проверки.
