# Дорожная карта SEMANTICGRAVITIFIELD

## Главный ориентир

Главная цель проекта — получение реальной экономической прибыли. Первая и текущая область реализации — исследование торговых возможностей.

Приоритет получает работа, которая приближает проект к обнаружению, независимой проверке и практической оценке прибыльных торговых возможностей. Инфраструктура, эксперименты и документация являются средствами, а не самостоятельными целями.

Не требуется завершать все возможные архитектурные контуры до начала исследования рынка. Необходимые компоненты развиваются по мере того, как они становятся реальным препятствием для исследовательского результата.

### Первая площадка: MEXC Futures

Для первого источника рыночных данных использовать публичный Futures WebSocket `wss://contract.mexc.com/edge` и REST market endpoints. Частные API-ключи не нужны для получения публичных рыночных данных.

При реализации адаптера учитывать официальный контракт данных:
- contract metadata содержит `priceScale`, `volScale`, `priceUnit`, `volUnit`, `contractSize`, `makerFeeRate`, `takerFeeRate` и состояние контракта;
- поток сделок `push.deal` содержит цену, объём, сторону сделки, transaction ID и временные метки;
- для JSON-подписки отключать агрегацию сделок параметром `compress: false`;
- для Protobuf-подписки явно задавать `reduce: false`, поскольку в документации отмечено включение `reduce` по умолчанию и выдача только одной записи за период;
- получать funding rate и время следующего расчёта funding отдельно;
- сохранять сырые сообщения, метаданные контракта и временные метки до преобразования в нормализованные события.

Комиссии нельзя считать универсальной константой: учитывать тип исполнения, фактические тарифы API аккаунта и данные конкретного контракта. Не подменять отсутствующие параметры значениями из примеров документации.

Официальные источники:
- https://www.mexc.io/api-docs/futures/integration-guide
- https://www.mexc.co/api-docs/futures/websocket-api/deal
- https://www.mexc.co/api-docs/futures/websocket-api/contract-data
- https://www.mexc.io/api-docs/futures/market-endpoints/get-funding-rate

## Постоянные правила

- Прибыль — конечная цель, но не гарантированное обещание.
- Торговая гипотеза не равна подтверждённой возможности.
- Историческая прибыль не равна будущей прибыли.
- Издержки и ограничения исполнения учитываются до заявления об экономическом преимуществе.
- Неопределённость, неполнота и отрицательные результаты сохраняются явно.
- Не строить универсальные механизмы заранее и не вводить искусственные запреты на будущее расширение.
- Не выполнять инфраструктурную работу, не объяснив, какое реальное препятствие она устраняет.
- Документация не требует отдельной ветки, PR или GitHub Action сама по себе.
- GitHub Actions запускаются при изменениях кода и технической конфигурации, но не при изменении только текстовой документации.

## Что не является критерием прогресса

- Количество документов и архитектурных схем.
- Количество абстрактных контуров, не имеющих работающей реализации.
- Количество найденных паттернов без независимой проверки.
- Успешный CI без проверки корректности экономического результата.
- Сложность системы сама по себе.
