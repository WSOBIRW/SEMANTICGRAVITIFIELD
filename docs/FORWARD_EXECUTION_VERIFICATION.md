# Причинная проверка исполнения после сигнала

**Версия:** 0.1.0  
**Статус:** Реализовано как отдельный API; интеграция в полный экспериментальный конвейер ещё не завершена.

## Назначение

Исключить ретроспективный выбор входа и выхода из того же временного окна, по которому сформирован исследовательский кандидат.

`evaluate_forward_round_trip` принимает уже сформированный кандидат и проверяет только последующие котировки. Время окончания окна кандидата считается моментом принятия решения.

## Правило выбора

1. Момент решения равен `candidate.end_time_ms`.
2. Момент решения не может быть раньше максимального времени получения (`received_time_ms`) всех событий, использованных при формировании кандидата. Это не позволяет использовать запоздавшую обучающую запись, а затем задним числом считать сигнал уже доступным.\n3. Вход — первая котировка того же инструмента и того же источника, у которой одновременно:
   - `event_time_ms >= decision_time_ms`;
   - `received_time_ms >= decision_time_ms`.
3. Горизонт удержания отсчитывается от времени получения входной котировки.
4. Выход — первая последующая котировка, у которой время события и время получения не меньше целевого времени выхода.
5. Если вход или выход не наблюдались, функция возвращает ошибку. Она не подставляет последнюю доступную котировку и не объявляет сделку успешной.
6. Экономическая оценка выполняется существующей функцией `evaluate_round_trip` только на выбранной паре котировок.

## Конфигурация командной строки

Если в JSON-конфигурации присутствует блок `economic`, на верхнем уровне обязательно задаётся положительное целое поле `holding_period_ms`. Без него экономическая оценка не запускается: горизонт удержания нельзя выбирать постфактум по результатам.

## Публичный интерфейс

`evaluate_forward_round_trip(events, candidate, holding_period_ms, config)`

Результат — `EconomicAssessment`. Ошибки причинного этапа представлены `ForwardVerificationError`.

## Проверки

Добавлены тесты, подтверждающие:
- котировки до момента сигнала не используются для входа, даже если они поступили позже;
- выход выбирается по первой котировке после заданного горизонта, а не по наиболее выгодной последующей котировке;
- отсутствие наблюдаемого выхода приводит к отказу от оценки.

## Ограничения и дальнейшая работа

- Это причинный выбор наблюдаемых котировок, но не симулятор исполнения.
- Не моделируются задержка доставки ордера, очередь, глубина стакана для размера позиции, частичное исполнение и проскальзывание, зависящее от объёма.
- Горизонт удержания должен быть задан до просмотра проверочного результата. Подбор горизонта на тестовой выборке создаёт множественное тестирование и смещение отбора.
- Данный API не реализует полный Walk-Forward, подбор параметров только на обучающей выборке, baseline или агрегированную статистическую проверку.
- Положительный результат одной сделки или одной выборки не является доказательством устойчивого преимущества.

## ЧЕМ НЕ ЯВЛЯЕТСЯ

- Не является торговым сигналом или рекомендацией открыть позицию.
- Не является гарантией исполнения по отображаемой котировке.
- Не является доказательством прибыльности, статистической значимости или устойчивости стратегии.
- Не заменяет независимую проверку размера позиции, contractSize, комиссий, funding settlements и рыночного воздействия.
