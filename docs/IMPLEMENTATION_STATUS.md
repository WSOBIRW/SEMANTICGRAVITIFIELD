# Статус реализации

## Текущая версия

Прототип: 0.1.0  
Язык: Rust  
Зависимости: только стандартная библиотека  
Назначение: проверка входных рыночных событий и первичный контур предотвращения ошибок.

## Реализовано

- Типизированное событие рынка с версией схемы.
- Раздельные временные метки события и получения в Unix milliseconds UTC.
- Представление котировки Bid/Ask целыми тиками и явным масштабом цены.
- Представление сделки целыми тиками и лотами.
- Проверка обязательных идентификаторов.
- Проверка неотрицательности временных меток.
- Предупреждение `ClockSkewSuspected`, если время события позже времени получения; без произвольного допуска и без автоматической коррекции часов.
- Проверка положительности цены и масштаба.
- Проверка crossed quote (Bid > Ask).
- Обнаружение повторного event_id с глобальной областью уникальности в пределах экземпляра валидатора.
- Конфигурируемая FIFO-дедупликация последних N идентификаторов через `EventValidator::with_dedup_capacity`; повтор за пределами окна может быть принят. `EventValidator::new` сохраняет неограниченный режим.
- Контроль строго возрастающей sequence отдельно для каждой пары source/instrument.
- Обнаружение разрыва sequence с точным числом пропущенных значений; событие принимается с предупреждением, watermark продвигается.
- Отдельные предупреждения и ошибки в отчёте EPE.
- Структурированные защитные finding и уровни серьёзности.
- Unit и интеграционные smoke-тесты.
- CI workflow для fmt, Clippy и cargo test.

## Ограничения прототипа

- Это не полноценная торговая система и не торговый сигнал.
- Пока нет сериализации и сетевого API.
- Нет постоянного хранилища и восстановления состояния после перезапуска.
- Нет автоматической коррекции часов или универсального допуска clock skew; подозрение фиксируется предупреждением.
- Нет буферизации и переупорядочивания out-of-order событий.
- Нет явного session_id и политики reset/reconnect для sequence.
- Дедупликация остаётся только в памяти и не восстанавливается после перезапуска. Ограниченный FIFO-режим имеет семантику повторного допуска после вытеснения; выбор ёмкости остаётся ответственностью вызывающего компонента.
- Нет проверки экономической целесообразности или реальной эффективности стратегий.
- CI проверяет fmt, Clippy и cargo test. Последний подтверждённый результат относится к конкретному SHA и не переносится автоматически на последующие изменения.

3. Добавить сериализацию состояния и детерминированное восстановление.
4. Связать дедупликацию с восстановлением и определить replay semantics.
5. Создать машиночитаемую схему внешнего контракта.

7. Подключить TRADINGCORE в режиме наблюдения после фиксации стабильного контракта.
